# Data card

All data is **synthetic**, generated by code with fixed seeds. No real person, company, ticket or
system is in this repo. Harrowmere Textiles is fictional, and every e-mail address uses the reserved
`.example` domain.

## What is generated

| File | Made by | Contents |
|---|---|---|
| `data/directory.json` | `itdesk/company.py` | 120 people in 7 departments: ID, name, manager, groups, device state |
| `data/tickets.jsonl` | `itdesk/tickets.py` | 600 tickets with text, sender, hidden system state and gold labels |
| `data/llm_triage.jsonl` | `scripts/run_llm.py` | qwen2.5-1.5b zero-shot category for every dev and test ticket (measured on CPU) |
| `data/llm_plans.jsonl` | `scripts/run_llm.py` | qwen2.5-1.5b free-form tool plan for every test ticket (measured on CPU) |
| `data/manifest.json` | `scripts/manifest.py` | SHA-256 of the four files above |

## Tickets

- Categories: password reset, access request, VPN, laptop for a new starter, outage, other.
- Each ticket hides the system state the agent must discover with read tools: a locked account, an
  expired VPN certificate, a non-compliant laptop, a degraded service, the real hiring manager.
- Gold labels: category, playbook, the knowledge-base article, priority (impact x urgency), the
  expected outcome (resolved, denied, escalated, linked to an incident) and the exact state changes a
  correct agent makes.
- Traps: resets for someone else, senders outside the company domain, requests to send a password to a
  personal address, privileged groups with and without a change reference, access for people the
  requester does not manage, laptops requested by someone who is not the hiring manager, and planted
  instructions aimed at "the AI agent" in about 8% of tickets.
- Split by a hash of the ticket ID: train 313, dev 100, test 187. Some wordings, and the "other"
  requests that sound like IT (a laptop charger, car park access, the guest wifi password), appear
  only in dev and test, so triage is measured on phrasing it never saw in training.

## Limits

Templated English text, one request per ticket, simple identity rules, no attachments or threads.
Real tickets are messier. The numbers describe this set, not service desks in general.
