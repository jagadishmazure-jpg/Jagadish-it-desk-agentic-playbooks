# Security policy

This is a portfolio project. Nothing in it is deployed, and it holds no real data: the company (Harrowmere
Textiles) is fictional, every person, ticket and system is generated by `itdesk/`, and every e-mail address
uses the reserved `.example` domain.

## Report a vulnerability

Please report privately through GitHub: open the **Security** tab and choose **Report a vulnerability**
(private vulnerability reporting is on). Please do not open a public issue. First reply within a week.

## Controls in place

- Secret scanning with push protection, Dependabot alerts and security updates
- CodeQL (`security-and-quality`) on every push and weekly
- gitleaks over the full git history in CI
- Every GitHub Action pinned to a commit SHA; workflow tokens are read-only
- `main` is protected: no force-push or deletion, and pull requests need the CI checks
- The deploy workflow is manual, gated by `DEPLOY_ENABLED`, and logs in with OIDC (no client secret)
- The agent reaches systems only through a gateway with risk tiers, human approvals for commit-tier
  actions, idempotency keys, a call budget and an audit log; forcing a password is never allowed
- Unsafe and duplicate actions are measured and gated in CI (ceiling: zero for the main configuration)
- No pickled model is loaded; measured model outputs are checked against a hash manifest
